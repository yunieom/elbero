- 선행 증거: [`T02 공공데이터 검증 기록`](../research/t02-f03-public-data-validation.md)
- G0 판단: 조건부 통과

- 노선별 검증 방식: API 간 값 차이와 데이터 제공 여부를 자동 수집하고 실제 정답은 수동 검증값으로 분리
- 완료된 노선 감사: KRIC 최신 코드표의 수도권 25개 노선 그룹 (2026-09-21)
- 전체 결과: [`수도권 도시철도 API 정보 차이 감사 요약`](../research/metropolitan-lines-api-sync-summary.md)

## 첫 지원 범위

| 여정 | 지원 방식 | 현재 결정 |
| --- | --- | --- |
| 답십리→강동 | 5호선 직통 | 2026-09-18 현장 확인된 1번 출구만 퇴장 경로로 사용하고 서울 상태 시설과 연결 |
| 답십리→굽은다리 | 5호선 하남검단산 방면 직통 | 2026-09-18 편의정보 확인으로 1번 출구 확정. 서울 상태 데이터는 2번 출구로 반환되어 1번 출구의 실시간 상태는 `unknown`이며 추천 시작 불가 |
| 답십리→홍대입구 | 5호선→2호선 환승 | 동대문역사문화공원을 우선 후보로 사용. 필수 승강기가 운행 중지 또는 미확인이면 을지로4가의 검증된 후보를 평가 |

위 세 대표 여정은 실시간 시설 연결까지 검증한 정적 후보를 유지한다. 그 밖의 5호선
56개 역 조합도 일반 노선 경로와 방향별 차량·문 안내를 반환한다. 다만 실시간 시설과
연결되지 않았거나 접근성 데이터가 비어 있는 경우에는 추천 경로로 확정하지 않고
`엘리베이터 안전 경로 미확인`으로 표시한다.

수도권 전체 API 차이 목록은
[`수도권 도시철도 API 정보 차이 감사 요약`](../research/metropolitan-lines-api-sync-summary.md)과 각 노선별 문서에
기록하며, 어떤 소스가 맞는지는 코드에서 자동 판정하지 않는다.

사용자가 지도·편의정보·현장으로 확인한 출구 값은
[`5호선 지상 출구 수동 검증값`](../../data/verification/line-5-surface-exits.json)에 원본 API와
분리해 기록한다. 2026-09-18 기준 차이가 발견된 35역의 출구 검증을 완료했다.

나머지 5호선 충돌 항목의 소스 선택과 방향별 차량·문 검증값은
[`5호선 접근성 안내 검증값`](../../data/verification/line-5-accessibility-guidance.json)에 기록한다.
운행 층은 `stationElevator`, 승강장·문별 이격거리는 `stationPlatformTrainDistance`를
사용한다. 인접 차량·문은 `stationElevatorCarNumber`를 기반으로 방향을 수동 검증하며,
사용자가 확정한 방향값은 API 원본과 분리한
[`5호선 수동 보정값`](../../data/verification/line-5-manual-overrides.json)을 우선한다.
나머지는 최신 승강장 API와 연결한다. `yellow` 문은 주의 경고와 함께 안내하고,
`red` 문은 추천에서 제외한다. 대체 후보가 바로 옆 문일 때는 계단에서 먼 문을 먼저
선택하고 그다음 이격거리가 작은 문을 선택한다. 계단 인접 차량·문 API를 사용할 수
없으면 이격거리가 작은 인접 안전 문을 선택하고, 그 값도 같으면 차량·문 번호가 앞선
후보를 사용한다. 즉 계단 인접 API 미등록은 `red` 대체 문 안내를 막지 않는다.

2026-09-28 재수집 기준 56역 모두의 방향별 레코드를 생성했다. 이 중 51역은 정적
데이터 연결이 완료됐고 4역은 부분 확인, 1역은 API 값 없음이다.

- 신길: 2번 승강장 `4-2`와 인접 문이 모두 `red`라 대체 추천 문이 없다.
- 강동: 사용자가 확정한 둔촌동 방면 `8-3` 외 천호·길동 방면이 미확정이다.
- 길동·하남검단산: 상·하행 코드와 종착역 코드가 충돌하는 승강장이 각각 1개 있다.
- 까치산: `stationElevatorCarNumber` 응답이 비어 있다.
- 을지로4가: 종로3가 방면 `10-4`는 5호선 이격거리 응답에 10호차가 없어 이격거리
  미확인 경고를 표시한다.

## 시설 상태 연결 규칙

KRIC와 서울교통공사 데이터에는 공통 시설 ID가 없다. 따라서 역 코드, 서울 승강기명,
운행 층, 설치 위치가 모두 검증표와 일치할 때만 시설 상태를 연결한다. 하나라도 달라지면
자동으로 비슷한 이름을 선택하지 않고 `unknown`으로 처리한다.

- `all`: 그룹의 모든 엘리베이터가 운행 중이어야 경로를 사용할 수 있다.
- `any`: 출구처럼 대체 가능한 시설 중 하나 이상이 운행 중이면 경로를 사용할 수 있다.
- `out_of_service`: 필수 시설이 `보수중`일 때 사용한다.
- `unknown`: 서울 상태 행이 없거나 검증된 연결 조건이 달라졌을 때 사용한다.
- 추천 경로는 모든 필수 그룹이 `operational`인 후보 중 우선순위가 가장 높은 하나다.

## G0 점검

| 항목 | 판정 | 근거 또는 제한 |
| --- | --- | --- |
| 방향별 출발역 진입 | 충족 | 답십리 마장·장한평 방면 KRIC 동선과 서울 내부·외부 승강기 연결 |
| 환승 경로 | 충족 | 동대문역사문화공원과 을지로4가의 방향별 KRIC 환승 단계 확인 |
| 도착역 퇴장 | 조건부 충족 | KRIC 진입 동선을 역순 사용한다고 응답 근거에 명시 |
| 현재 승강기 상태 | 조건부 충족 | 서울 API는 최대 1시간 지연되고 행별 관측 시각이 없음 |
| 고장 시 대체 환승 | 대표 여정 충족 | 동대문역사문화공원 필수 시설 고장 fixture에서 을지로4가 선택 |
| 5호선 전체 역 조합 | 조건부 충족 | 56역의 일반 경로와 정적 차량·문 안내 제공. 미확정 정보와 실시간 시설 미연결은 안전 경로 미확인 표시 |
| 1~9호선 전체 지원 | 미충족·후속 범위 | 5호선 기능 연결과 UI/UX QA 후 차례로 연결 |

G0는 대표 여정을 구현할 근거가 확보되었다는 의미로만 통과한다. 전체 서울 지하철의
무장애 경로가 검증되었다는 의미가 아니다.

## API 증거

```text
GET /journeys/plan?originStationCode=2543&destinationStationCode=2549
GET /journeys/plan?originStationCode=2543&destinationStationCode=2551
GET /journeys/plan?originStationCode=2543&destinationStationCode=239
GET /journeys/plan?originStationCode=2534&destinationStationCode=2558
GET /journeys/plan?originStationCode=2561&destinationStationCode=2565
```

응답에는 정적 경로 데이터 버전, 검증일, 서울 상태 수집 시각, 최대 지연 시간, 후보별
차단 이유, 시설별 연결 여부와 원본 상태를 포함한다.
