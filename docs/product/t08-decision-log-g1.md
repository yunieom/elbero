## 2. 관찰 결과

| 흐름 | 관찰 결과 | 막힌 지점 | 판정 |
| --- | --- | --- | --- |
| 정상 여정 | 출발·도착 검색, 경로 요약, 진입·탑승·환승·퇴장 카드가 한 방향으로 읽힌다. 차량·문과 승강장 간격은 탑승 카드에서 확인한다. | 없음 | 통과 |
| 출발·도착 입력 | 출발역 검색어가 도착역 입력에 남으면 잘못된 역을 선택할 가능성이 있었다. | 검색 상태 공유 | 검색어를 입력 필드별로 분리해 해결 |
| 지상 엘리베이터 | 출구 후보가 하나인데도 “출구 중”이라고 표시하면 실제 선택지가 있는 것처럼 읽혔다. | 후보 수와 문구 불일치 | 1개는 “N번 출구 쪽”, 복수는 “N, M번 출구 중”으로 분기해 해결 |
| 승강장 안전 정보 | 간격 설명을 별도 카드와 긴 문장으로 반복해 핵심 이동 순서가 분산됐다. | 정보 중복 | 탑승 카드 안에 `안전/주의 · 승강장 간격 Ncm` 아이콘으로 통합 |
| 안전 경로 미확인 | 제목·설명·확인 항목이 여러 카드로 갈라져 같은 상태를 반복했다. | 상태 이해 지연 | 하나의 상태 카드로 통합 |
| 운행 중지 | 필수 승강기가 `보수중`이면 일반 경로와 안전 추천의 차이를 구분해야 한다. | 대체 경로가 항상 존재하지 않음 | 운행 중지 시설을 명시하고 다른 후보 또는 검색 복귀를 제공 |
| 경로 없음 | 모든 후보가 고장 또는 red로 제외된 경우 빈 결과처럼 보일 수 있었다. | 실패 의미 불명확 | `NO_ACCESSIBLE_ROUTE`로 분리하고 안전 경로가 없음을 명시 |
| 조회 실패·오프라인 | 외부 API 실패와 데이터 부족이 같은 오류처럼 보일 수 있었다. | 복구 행동 불명확 | 조회 실패는 재시도, 오프라인은 선택 유지·제한 복구, 데이터 부족은 일반 경로+미확인으로 분리 |
| 양 플랫폼 | 동일 Expo Router 진입점으로 iOS와 Android에서 첫 화면과 역 검색 진입이 가능했다. | `SafeAreaView` 사용 중단 예정 경고 | 실행 기반은 통과, 컴포넌트 교체는 후속 유지보수 |

## 3. Decision Log

| ID | 결정 | 이유 | 적용 상태 |
| --- | --- | --- | --- |
| D-01 | 출발역·도착역 검색어와 선택 상태를 각각 보관한다. | 한 입력의 검색어가 다른 입력에 남는 오선택을 방지한다. | 적용 |
| D-02 | 지상 출구 후보가 한 개면 “N번 출구 쪽 지상 엘리베이터”, 복수면 “N, M번 출구 중 목적지와 가까운 지상 엘리베이터”로 안내한다. | 실제 선택지 수와 문장을 일치시킨다. | 적용 |
| D-03 | 출처명·원본 근거·충돌 상세는 사용자 화면에 노출하지 않고 내부 감사 문서에서 관리한다. | 사용자는 결정된 행동과 필요한 경고에 집중해야 한다. | 적용 |
| D-04 | 차량·문과 승강장 이격거리를 열차 이동 카드에 합치고 별도 이격거리 카드를 두지 않는다. | 행동에 필요한 안전 정보를 같은 맥락에서 읽게 한다. | 적용 |
| D-05 | 이격거리 0~10cm는 green, 10cm 초과~15cm는 yellow 경고, 15cm 초과는 red로 추천에서 제외한다. | 수치와 추천 정책을 일관되게 연결한다. | 적용 |
| D-06 | 사용자 안내 출구와 실시간 시설 상태 연결은 서울교통공사 가동현황을 우선하고, 누락 시 검증된 KRIC·수동 보정값을 사용한다. | 실제 가동 상태와 사용자 안내를 연결하되 출처 차이를 사용자에게 전가하지 않는다. | 적용 |
| D-07 | 인접한 출구 번호 차이처럼 동일 시설임을 확인할 수 있는 경우에만 내부 보정을 허용한다. 확인할 수 없으면 추정하지 않는다. | 잘못된 안전 경로 추천을 막는다. | 적용 |
| D-08 | 안전 경로 미확인은 제목·설명·확인 항목을 하나의 카드로 보여 준다. | 반복을 줄이고 다음 행동을 분명히 한다. | 적용 |
| D-09 | 방향은 종착역을 우선 표시하고, 바로 인접한 차량·문 후보는 red가 아닌 후보 중 하나를 선택한다. | 사용자가 승강장에서 실제 표지와 빠르게 대조할 수 있게 한다. | 적용 |
| D-10 | 데이터가 없으면 일반 지하철 경로는 유지하되 `엘리베이터 안전 경로 미확인`으로 표시한다. | 데이터 누락을 시설 부재나 안전 경로로 오인하지 않는다. | 적용 |
| D-11 | 실제 위치처럼 보이는 실시간 추적 표현은 사용하지 않고 단계 순서와 현재 단계만 보존한다. | 현재 데이터로 검증할 수 없는 위치 정확도를 암시하지 않는다. | 설계 확정, T15·T17 구현 예정 |

## 4. G1 설계 관문 판정

| 관문 | 판정 | 근거 |
| --- | --- | --- |
| 핵심 과업 흐름 | 통과 | 검색→요약→진입→탑승→환승→퇴장과 오류 복귀 흐름이 정의되어 있다. |
| 정보 우선순위와 사용성 | 통과 | 사용자 행동, 상태, 안전 간격을 우선하고 원본 근거와 중복 카드를 제거했다. |
| 오류·불확실성 처리 | 통과 | 운행 중지, 안전 경로 미확인, 경로 없음, 조회 실패, 오프라인을 서로 다른 상태로 정의했다. |
| 데이터·시스템 계약 | 통과 | 원본 수집부터 경로 엔진·API·앱 mapper·저장 복구까지 책임과 오류 코드가 분리되어 있다. |
| 양 플랫폼 개발 기반 | 통과 | iPhone 18 Pro/iOS 27.0과 Android 16(API 36) 에뮬레이터에서 공통 앱을 실행했다. |
| 접근성 설계 | 통과 | 색상 외 문구·아이콘, 최소 터치 영역, 세로 읽기 순서, 글자 확대 원칙을 정의했다. |

### 최종 판정

G1은 **통과**로 판정한다. Phase 2 구현을 시작하는 데 필요한 UX 구조, 오류 정책, 시스템 계약과
양 플랫폼 실행 기반이 준비됐다. 아래 후속 항목은 G1을 막지 않지만 출시 판단 전에 반드시
검증해야 한다.

## 5. 남은 제한과 다음 작업

- 현재 사용자 QA와 상세 경로 구현은 5호선이 중심이다. 1~9호선과 수도권 전철 확대는 같은
  계약과 화면 구조를 재사용하되 노선별 데이터 검증이 필요하다.
- 실제 고장 시설이 포함된 운영 응답과 모든 후보가 제외되는 사례는 Phase 2 통합 테스트에서
  다시 검증한다.
- 단계별 이전·다음과 현재 단계 보존은 T15·T17에서 구현한다.
- 실제 제보·도움말 전송은 T18에서 구현한다.
- iOS·Android 실기기 키보드, 뒤로 가기, 최대 글자 크기, VoiceOver·TalkBack, 실제 오프라인
  복구는 T21에서 검증한다.
- React Native `SafeAreaView` 경고는 `react-native-safe-area-context` 기반으로 교체한다.

T08 완료 조건인 관찰 결과, 수정 결정, G1 판정, 검증 증거, 남은 제한과 다음 작업을 모두
기록했다.
