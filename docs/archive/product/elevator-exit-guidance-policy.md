# 엘리베이터 출구 안내·상태 결합 정책

- 결정일: 2026-09-28
- 적용 범위: 5호선 QA 이후 지원하는 모든 노선
- 목적: 출처별 출구 번호 차이를 내부에서 관리하면서 사용자에게는 단순하고 실행 가능한 안내를 제공

## 사용자 안내 출구 우선순위

1. 서울교통공사 승강기 가동현황 `SeoulMetroFaciInfo`의 설치 위치
2. KRIC `stationElevator` 시설 현황의 출구 번호
3. 지도·편의정보·현장 확인으로 기록한 수동 검증값
4. 위 값이 모두 없으면 출구 번호를 추정하지 않고 `안전 경로 미확인` 표시

서울 가동현황을 우선하는 이유는 사용자에게 보여 주는 출구와 실시간 상태를 같은 시설 레코드에
연결하기 위해서다. 원본 API 응답은 수정하지 않고 검증 데이터와 제품용 안내만 별도로 정규화한다.

## 인접 출구 번호가 다른 경우

- 같은 역·운행 층·시설명으로 확인되고 엘리베이터가 인접한 두 출구 사이에 있는 경우, 한 API가
  1번이고 다른 API가 2번이어도 실시간 상태 연결을 유지할 수 있다.
- 사용자 안내에는 우선순위가 높은 출구 번호 하나만 표시한다.
- `1번과 2번 API가 충돌한다` 같은 원본 차이는 사용자에게 표시하지 않는다.
- 어떤 시설을 결합했는지와 원본별 값은 감사·검증 문서에만 기록한다.
- 역·운행 층·시설 식별이 불명확하거나 인접 시설이라는 근거가 없으면 결합하지 않고
  `안전 경로 미확인`으로 처리한다.

## 굽은다리 적용값

| 용도 | 적용값 |
| --- | --- |
| 사용자 출구 안내 | 2번 출구 |
| 실시간 시설 | `승강기)엘리베이터-굽은다리 외부3` |
| 운행 구간 | `B1-1F` |
| 서울 설치 위치 | `2번 출입구` |
| 원본 차이 기록 | `stationMovement`·`stinElevatorMovement`는 1번, `stationElevator`·`SeoulMetroFaciInfo`는 2번 |

## 화면 표시 원칙

- 출구 번호, 현재 이용 가능 여부, 사용자가 해야 할 행동만 표시한다.
- API 명, 원본 근거, 출처 충돌의 상세 설명은 표시하지 않는다.
- 경로 상태와 확인이 필요한 내용은 하나의 상태 카드에 합친다.
- 승강장 이격거리 표시는 별도 단계가 아니라 해당 승차 카드에 포함한다.
