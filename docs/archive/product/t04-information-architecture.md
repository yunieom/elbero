# T04 · S01~S06 정보 구조와 행동 순서

- 확정일: 2026-09-28
- 상태: **완료**
- 연결 기능: F01~F09 · 탐색부터 단계별 안내
- 선행 결정: [`T03 대표 여정 지원 범위와 G0`](./t03-g0-support-scope.md)
- 구현 증거: [`5호선 실시간 승강기·앱 UI QA 명세`](./line-5-live-ui-qa.md)

## 설계 원칙

1. 지도 조작 없이 역 검색과 텍스트 카드만으로 전체 여정을 이해할 수 있어야 한다.
2. 한 화면의 주요 행동은 하나로 두고, 출발·도착 선택 후 `안전 경로 찾기`로 진행한다.
3. 승강기 운행 상태와 승강장 간격은 색상만 쓰지 않고 아이콘·수치·문구를 함께 쓴다.
4. 출처가 충돌하거나 시설 연결이 확인되지 않으면 일반 경로는 유지하되
   `안전 경로 미확인`으로 표시한다.
5. 데이터 출처별 원본 차이는 내부 검증 문서에서 관리하고 사용자에게는 결정된 안내와
   필요한 경고만 보여 준다.

## 화면 구조

| 화면 | 사용자가 확인하는 정보 | 주요 행동 | 상태와 예외 | 구현 경계 |
| --- | --- | --- | --- | --- |
| S01 홈 | 서비스 목적, 승강기 상태 반영과 최대 지연 안내 | 출발역 또는 도착역 선택 | 역 목록 로딩 실패 시 재시도 | 5호선 QA 구현 완료 |
| S02 역 선택 | 노선, 역명 검색 결과, 현재 선택 역 | 역 선택, 닫기 | 검색 결과 없음, 목록 로딩 실패 | 5호선 56역 구현 완료 |
| S03 여정 요약 | 출발→도착, 노선, 환승 여부, 추천 가능 상태 | 이동 순서 확인 | 이용 가능·운행 중지·안전 경로 미확인 | 5호선 QA 구현 완료 |
| S04 단계별 안내 | 진입·개찰·탑승·환승·퇴장 순서, 차량·문, 승강장 간격 | 위에서 아래로 순서 확인, 검색으로 복귀 | yellow 경고, red 추천 제외, 위치 미확인 | 5호선 직통·분기·대표 환승 구현 완료 |
| S05 시설·상태 | 여정에 필요한 승강기별 상태, 확인 시각, 최대 지연, 경로 검증일 | 상태와 확인 시각 확인 | 시설 연결 누락은 `미확인`, 보수중은 `운행 중지` | 결과 화면 하단에 구현 완료 |
| S06 제보·도움말 | 잘못된 정보 제보 항목, 현재 여정 식별값, 도움말과 연락 경로 | 제보 작성 또는 도움말 열기 | 전송 실패 시 입력 보존과 재시도 | T18에서 구현 |

S06은 T04에서 구조와 진입점을 설계하고 실제 입력·전송·연락 기능은 T18에서 구현한다.
S01~S05의 현재 구현은 5호선 QA 범위이며, 다른 노선은 같은 정보 구조를 재사용한다.

## 정상 행동 순서

```text
S01 홈
  → 출발역 선택
S02 역 선택
  → 역명 검색 → 출발역 확정
S01 홈
  → 도착역 선택
S02 역 선택
  → 역명 검색 → 도착역 확정
S01 홈
  → 안전 경로 찾기
S03 여정 요약
  → 추천 상태와 환승 여부 확인
S04 단계별 안내
  → 진입 → 탑승 → 환승(필요한 경우) → 퇴장
S05 시설·상태
  → 필수 승강기 상태와 데이터 확인 시각 확인
  → 다른 역으로 검색 또는 S06 제보·도움말
```

출발역과 도착역을 바꾸면 두 선택값만 교환하고 검색어는 공유하지 않는다. 같은 역을
선택하면 결과 화면으로 이동하지 않고 해당 입력 화면에서 오류를 안내한다.

## 여정 결과의 정보 우선순위

1. `현재 이용 가능`, `운행 중지 시설 있음`, `안전 경로 미확인` 상태
2. 출발역·도착역과 환승 여부
3. 순서가 있는 이동 카드
4. 탑승 차량·문과 승강장 간격 아이콘
5. 여정에 필요한 실시간 승강기 상태
6. 상태 확인 시각·최대 지연·경로 검증일
7. 다른 역 검색과 제보·도움말

승강장 간격은 별도 설명 문장으로 반복하지 않는다. 열차 이동 카드 안에
`안전 · 승강장 간격 9cm` 또는 `주의 · 승강장 간격 12cm`처럼 표시한다. `red` 후보는
추천 경로에 포함하지 않는다.

## 오류와 복구 흐름

| 상황 | 화면 처리 | 사용자의 다음 행동 |
| --- | --- | --- |
| 역 목록 로딩 실패 | S02 안에 원인 요약과 재시도 버튼 | 다시 시도 또는 닫기 |
| 일치하는 역 없음 | 검색 결과 영역에 빈 상태 표시 | 검색어 수정 |
| 출발·도착 동일 | S01 입력 영역 아래 검증 문구 | 한쪽 역 변경 |
| 여정 API 실패 | 결과 화면에 오류 요약과 재시도 버튼 | 다시 시도 또는 뒤로 이동 |
| 필수 시설 운행 중지 | 경로 상태와 해당 시설 상태를 함께 표시 | 다른 경로 확인 또는 검색 복귀 |
| 위치·상태 미확인 | 일반 경로와 하나의 미확인 카드로 통합 | 현장 안내 확인 또는 제보 |

## 접근성 기준

- 모든 버튼의 최소 터치 영역은 48px로 한다.
- 화면 제목은 헤더 역할을 제공하고 로딩·오류는 라이브 영역으로 알린다.
- 차량·문, 출구, 간격 수치는 장식 요소가 아니라 접근성 레이블에도 포함한다.
- 성공·주의·위험·미확인을 색상만으로 구분하지 않는다.
- 큰 글자에서도 카드의 읽기 순서와 주요 행동이 잘리지 않게 세로 스크롤을 유지한다.

## 남은 제한과 다음 작업

- S06 제보·도움말의 실제 입력·전송은 T18 범위다.
- 단계별 이전·다음과 현재 단계 보존은 T15·T17에서 구현한다.
- iOS·Android 실제 기기, 큰 글자, 스크린리더 검증은 T21에서 수행한다.
- 현재 UI 구현은 5호선 범위이므로 1~9호선 확장 시 노선 배지·동명이역·환승 요약을
  같은 구조 안에서 확장해야 한다.

이 문서는 S01~S06 정상 흐름, 결과물 근거, 남은 제한과 다음 작업을 기록하므로 T04의
설계 완료 기준으로 사용한다.
