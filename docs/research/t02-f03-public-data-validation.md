# T02 · F03 공공데이터 검증 기록

- 확인일: 2026-09-17
- 범위: 답십리 → 홍대입구, 동대문역사문화공원 환승과 을지로4가 대체 환승
- 상태: 등록된 정확한 서비스·오퍼레이션으로 재검증 완료, 25개 표본 모두 정상

## 먼저 내린 결론

KRIC의 표준 이동경로 API는 출발역 진입, 환승, 도착역 퇴장을 **방향 조건이
있는 순서 데이터**로 조합하는 F03의 기반으로 사용할 수 있다. 현재 승강기 상태는
[서울교통공사 교통약자 이용시설 승강기 가동현황](https://data.seoul.go.kr/dataList/OA-15994/S/1/datasetView.do)의
`USE_YN`으로 보강할 수 있다. 이 데이터는 매시 갱신되지만 KRIC와 공통 시설 ID가 없고
행별 상태 관측 시각도 제공하지 않으므로, 검증된 시설 연결표 없이 특정 KRIC 경로를
자동 제외하면 안 된다.

첫 구현은 다음처럼 경계를 나눈다.

1. 검증된 정적 이동경로로 지상 → 승강장 → 환승 → 지상 여정을 조합한다.
2. 서울교통공사 상태를 `operational`, `out_of_service`, `unknown`으로 정규화한다.
3. 서울 데이터의 승강기명·운행구간·설치위치를 KRIC의 층·상세 위치와 대조한 수동
   검증 연결표를 운영한다.
4. `out_of_service` 상태와 KRIC 경로 연결이 모두 확인된 경우에만 해당 구간을 제외하고
   대체 환승을 계산한다.

KRIC API는 JSON/XML REST 형식이며 포털 명세에 `활용신청`과 `serviceKey`가
표시되어 있다. KRIC 소스의 이용허락범위는 포털에 `저작권표시`로 기재되어 있으므로
앱과 데이터 패키지에 출처를 남긴다.

서울 API 호출 형식은
`/json/SeoulMetroFaciInfo/{START_INDEX}/{END_INDEX}/`이다. 공식 샘플의 전체 건수는
2,820건이고 한 번에 최대 1,000건을 요청할 수 있으므로 전체 동기화는 3페이지로 나눈다.
`ELVTR_SE=EV`로 엘리베이터만 거른다. 실제 전체 응답에서 확인한 `USE_YN` 값은
`사용가능`, `보수중` 두 가지이며 각각 `operational`, `out_of_service`로 정규화한다.
새 값이 들어오면 `unknown`으로 처리한다. API 키는 `SEOUL_OPEN_DATA_API_KEY`
환경변수로 분리한다.

## 2026-09-17 실제 호출 결과

`apps/api/.env`의 `KRIC_SERVICE_KEY`를 노출하지 않고 25개 표본 요청을 검사했다.
KRIC는 HTTP 200 안에 자체 결과 코드를 담으므로 `header.resultCode`까지 확인해야 한다.
수집기는 `resultCode="00"`만 성공으로 판정하고, 그 외에는 종료 코드를 실패로 반환하도록
수정했다.

활용신청 반영 후 공식 노선 응답의 4자리 역 코드와 등록된 정확한 서비스·오퍼레이션을
사용해 다시 수집했다. 답십리→강동·굽은다리 표본을 추가한 현재 결과는 25개 표본 모두 정상이다. 처음 사용했던
`handicapped/transferMovement`와 `vulnerableUserInfo/stationElevatorMovement`는 신청이
덜 된 것이 아니라 이번에 등록된 API와 서로 다른 경로였다.

| API | 표본 결과 | 판정 |
| --- | --- | --- |
| `trainUseInfo/subwayRouteInfo` | 2호선 51역, 5호선 56역 | 정상 |
| `handicapped/stationMovement` | 답십리 양방향 진입 각 12건, 홍대입구 6건, 강동 14건, 굽은다리 6건 | 정상 |
| `vulnerableUserInfo/transferMovement` | 동대문역사문화공원 18단계, 을지로4가 8단계 | 정상 |
| `convenientInfo/stPlf` | 답십리·동대문역사문화공원·을지로4가·굽은다리 각 2개 승강장 | 정상 |
| `vulnerableUserInfo/stationPlatformTrainDistance` | 답십리 승강장별 32건, 합계 64개 차량·문 | 정상 |
| `vulnerableUserInfo/stationElevatorCarNumber` | 동대문역사문화공원 2건, 을지로4가 3건, 강동 2건, 굽은다리 2건 | 정상 |

| `trafficWeekInfo/stinElevatorMovement` | 동대문역사문화공원 70단계, 을지로4가 32단계 | 정상 |

답십리 진입 경로는 2번 출구와 6번 출구에서 각각 마장 방면 승강장까지 이어지는 6단계
경로를 반환했다. `2번 출구 옆 엘리베이터 → B2 대합실 → 승차 태그 → 승강장 방향
엘리베이터 → B3 마장 방면 승강장 → 승차`라는 첨부 화면의 텍스트와 실제 응답이 일치한다.

답십리 승강장 정보는 2건이 반환됐다. 두 승강장 모두 지하 3층 상대식 승강장이며,
`plfNo=1/updnDvCd=1`과 `plfNo=2/updnDvCd=2`가 확인됐다. 스크린도어와 안전발판은
모두 있음으로 응답됐다. 이격거리는 두 승강장 64개 차량·문에서 `sfDst=7~9`였으며 첨부
화면 기준으로 모두 첫 구간에 해당한다. 단, 공식 명세에서 단위를 확인하기 전에는 숫자에
임의의 단위를 붙이지 않는다.

동대문역사문화공원 환승 API는 요청한 5호선→2호선 홍대입구 방향에 대해 5호선 양쪽
도착 방향별 9단계씩 총 18단계를 반환했다. 실제 안내는 `5호선 승강장 하차 → 4호선 방향
환승 엘리베이터 → B3 4호선 승강장 → 대합실 방향 엘리베이터 → B1 대합실 → 2호선
대합실 → 2호선 을지로4가 방면 엘리베이터 → B2 승강장 → 승차`로 이어진다.

을지로4가 대체 환승 API는 5호선 양쪽 도착 방향별 4단계씩 총 8단계를 반환했다. 실제
안내는 `5호선 승강장 하차 → 대합실 방향 엘리베이터 → B2 2호선 을지로3가 방면
승강장 → 승차`로 이어진다. 따라서 두 환승역 모두 방향별 텍스트 동선을 구성할 수 있고,
동대문역사문화공원의 경로가 더 길다는 차이도 경로 선택 정보로 사용할 수 있다.

역사 내 엘리베이터 이동동선 API의 70건·32건은 단일 경로의 단계 수가 아니라 해당 역의
출입구-승강장 경로와 여러 방향의 환승경로를 모두 합친 결과다. 화면에 표시할 때는
`mvPathDvCd`, `mvPathMgNo`, `mvTpOrdr`로 경로를 나눠야 한다.

답십리→강동은 환승 없이 5호선 장한평 방면 승강장을 이용한다. 답십리에서는 2번 또는
6번 출구 옆 엘리베이터로 B2 대합실에 내려간 뒤 승강장 엘리베이터로 B3까지 이동한다.
강동역 도착 승강장의 엘리베이터 인접 위치는 8호차 4번 문이며, 답십리의 해당 문 위치
`sfDst`는 9다. 강동역의 출입구-승강장 응답에는 1번 출구 6단계와 2-1번 출구 8단계가
있다. 이 API는 지상→승강장 순서만 제공하므로 도착역 퇴장 안내는 같은 시설 동선을
역순으로 재구성한 것임을 제품과 검증 문서에 명시한다.

답십리→굽은다리는 5호선 하남검단산·상일동 방면 직통 열차를 이용하며 마천 방면
열차는 강동에서 다른 지선으로 갈라지므로 제외한다. 굽은다리 명일 방면 승강장
엘리베이터 인접 위치는 3호차 2번 문이고, 답십리 승강장 2의 해당 문 위치 `sfDst`는
9다. 굽은다리 내부 엘리베이터는 B2-B1, 명일 방면 3-2와 3-3 사이로 KRIC 시설과
서울 상태 데이터가 일치하며 현재 `사용가능`이다. 지상 엘리베이터는 KRIC 시설과 서울
상태 데이터가 모두 2번 출구로 표시하지만 KRIC 이동경로 문장만 1번 출구라고 표시한다.
따라서 현장 확인 전에는 지상 연결을 `unknown`으로 두고 안전한 완료 여정으로 추천하지
않는다.

처음 사용한 3자리 번호는 서울 지하철의 익숙한 역번호와 어긋났다. `subwayRouteInfo`의
실제 응답은 답십리 `2543`, 마장 `2542`, 동대문역사문화공원 `2537`, 을지로4가 `2536`이다.
`stPlf`는 축약 코드도 응답했지만 다른 API는 4자리 코드를 사용해야 데이터를 반환했다.
앞으로는 화면 표기용 역번호를 요청 코드로 추정하지 않고 노선 API가 반환한 코드를 그대로 쓴다.

원본 응답은 Git에서 제외된 `data/research/t02/raw/`에 보관했다.

## 대표 여정 방향 조건

아래 코드는 `subwayRouteInfo` 실제 응답에서 역명·호선·운영기관·인접 순서를 대조한 값이다.

| 구간 | 후보 요청 조건 | 확인하려는 것 |
| --- | --- | --- |
| 답십리 진입 | 5호선 `stinCd=2543`, `nextStinCd=2542`(마장) | 홍대입구 방면으로 가는 승강장 진입 동선 |
| 동대문역사문화공원 환승 | 출발 5호선 `stinCd=2537`, 대상 2호선, 대상선 인접역 `206`(신당)·`204`(을지로4가) | 2호선 홍대입구 방향 환승 단계와 포함 시설 |
| 을지로4가 대체 환승 | 출발 5호선 `stinCd=2536`, 대상 2호선, 대상선 인접역 `205`(동대문역사문화공원)·`203`(을지로3가) | 동일 목적지로 이어지는 대체 환승 단계와 포함 시설 |
| 홍대입구 퇴장 | 2호선 `stinCd=239`, `nextStinCd=238`(합정) | 해당 진행 방향에서 승강장→지상 퇴장 동선 |

`transferMovement`는 현재 선·역과 함께 환승 대상선 양쪽의 인접 역 코드를 전달한다.
이번 실제 응답에서도 요청한 2호선 홍대입구 방향 경로가 반환됐다. 파라미터 이름만 보고
`prevStinCd`를 출발선의 직전 역이라고 해석하지 않고, 대상선의 양쪽 인접 역을 함께
전달하는 것으로 구현한다.

요청 목록은 [`tools/kric/t02-queries.json`](../../tools/kric/t02-queries.json)에
기계 판독 가능한 형태로 기록했다.

## 화면 표현 결정

첨부된 철도역 편의정보의 복잡한 역사 그림은 원본 검증 자료로 사용하되, 앱의 기본
안내는 아래처럼 순서가 있는 텍스트 카드로 변환한다.

1. **진입:** `2번 출구 옆 엘리베이터를 타고 B2 대합실로 이동하세요.`
2. **개찰:** `교통카드를 태그한 뒤 마장 방면 엘리베이터를 이용하세요.`
3. **승강장:** `B3 마장 방면 승강장으로 이동하세요.`
4. **탑승:** 권장 차량·문과 엘리베이터 인접 위치를 함께 표시한다.
5. **주의:** 해당 문 위치의 승강장 이격거리를 낮음·주의·높음으로 표시한다.
6. **환승:** 환승이 있으면 하차 위치부터 다음 승강장까지 `transferMovement` 단계를
   이어 붙인다.
7. **퇴장:** 마지막 역의 승강장부터 지상 엘리베이터까지 순서대로 표시한다.

`sfDst` 단위는 cm로 사용한다. `0cm 이상~10cm 이하`는 `green` 안전,
`10cm 초과~15cm 이하`는 `yellow` 유의, `15cm 초과`는 `red` 추천하지 않음으로
분류한다. 색상만으로 위험을 전달하지 않고 수치·아이콘·문구를 함께 표시한다.

## F03 정규화에 필요한 최소 연결키

| 연결 | 필요한 키 | 현재 판단 |
| --- | --- | --- |
| 역과 호선 | `railOprIsttCd + lnCd + stinCd` | 공식 API에 공통으로 존재 |
| 방향 | 진입은 `nextStinCd`, 환승은 대상선과 인접역 쌍 | 대표 여정 실제 응답으로 조합 확인 |
| 이동 단계 | `mvPathMgNo + 순서 필드` | 공식 출력에 존재 |
| 승강장과 차량·문 | `plfNo` + 승강장 방향 정보 | 두 API 결합 필요 |
| 이동 단계와 실제 엘리베이터 | KRIC 층·상세위치 ↔ 서울 승강기명·운행구간·설치위치 | 공통 ID 없음. 검증된 수동 연결표 필요 |
| 고장 상태 | 서울 `USE_YN` + 수집시각 + 출처 | 매시 갱신 상태 사용 가능. 행별 원본 관측 시각은 없음 |

## 누락과 위험

- 서울 승강기 가동현황은 매시 갱신되지만 각 행의 원본 상태 관측 시각을 제공하지 않는다.
- 서울 응답에는 안정적인 시설 ID가 없고 KRIC와 역코드 체계도 다르므로, 역명·호선·층·
  위치를 검증한 연결표가 필요하다.
- 확인된 `USE_YN` 값은 `사용가능`, `보수중`이지만 이후 새 값이 추가될 가능성에 대비해
  알 수 없는 값은 `unknown`으로 처리해야 한다.
- `mvPathMgNo`는 이동경로 관리번호이지 승강기 일련번호라고 명시되어 있지 않다.
- 인접 차량·문 API는 승강장번호를 주지만 방향을 직접 주지 않는다.
- 정적 엘리베이터 파일은 상태와 기준일을 포함하지만 현재 고장을 반영하는 자료가
  아니다.
- 서울시 지상 위치 데이터는 내부 층·개찰구·승강장 연결을 제공하지 않는다.
- 따라서 동대문역사문화공원 고장 시 을지로4가를 선택하는 규칙은 서울 상태 행과 KRIC
  환승 단계 사이의 시설 연결표를 검증한 다음 활성화한다.

   함께 표시한다.
