# 실기기 출시 QA 체크리스트

이 문서는 iPhone과 Android에서 첫 출시 전 반드시 확인할 동작을 한곳에 모은 실행용 체크리스트다. 자동 테스트 결과는 [`release-validation.md`](./release-validation.md), 노선별 원천 데이터 확인은 [`지원 노선 검증 대기 목록`](../research/supported-lines-user-verification-pending.md)에서 별도로 관리한다.

> 현재 iPhone·Android에 설치된 Expo Go 또는 개발 빌드에서는 `QA 예시 채우기`와 `QA 예외 상태 시제품 보기`가 보이는 것이 정상이다. `production` 프로필로 만든 심사 빌드에서는 홈의 두 진입점이 렌더링되지 않으며 `/qa/states`를 직접 열어도 홈으로 이동한다.

## 2. 시작 전 준비

- [ ] 맥미니에서 API, 웹, Metro 컨테이너가 실행 중이다.
- [ ] `http://<맥미니 IP>:3000/health`가 정상 응답한다.
- [ ] 휴대폰과 맥미니가 같은 네트워크에 연결되어 있다.
- [ ] iPhone의 Expo Go와 Metro를 실행하는 Expo CLI가 같은 Expo 계정으로 인증되어 있다.
- [ ] 첫 실행 검증을 위해 기존 Expo Go 프로젝트 기록 또는 설치 앱 데이터를 한 번 초기화한다.
- [ ] 재실행·복구 검증을 위해 초기화하지 않은 두 번째 실행도 별도로 수행한다.
- [ ] 테스트 중 발견한 문제에는 기기, 출발역, 도착역, 단계 번호와 화면 캡처를 남긴다.

## 3. 필수 대표 여정

아래 두 경로는 출시 관문의 대표 동선이다.

### 직통: 답십리 → 강동

- [ ] 검색 결과에서 두 역과 5호선 배지가 정확하다.
- [ ] 출발역 지상 엘리베이터, 개찰구, 이동 층, 승강장 방향이 순서대로 표시된다.
- [ ] 열차 진행 방향과 종착역행 표기가 실제 진행 방향과 일치한다.
- [ ] 권장 차량·문과 승강장 간격 상태가 서로 모순되지 않는다.
- [ ] 도착역에서는 `빠른하차`로 표시되고 지상 출구까지 안내된다.

### 환승: 답십리 → 홍대입구

- [ ] 일반 지하철 경로는 데이터 누락 여부와 관계없이 끝까지 표시된다.
- [ ] 5호선에서 2호선으로 갈아타는 역, 방향과 환승 순서가 맞다.
- [ ] 환승 전에는 `빠른환승`, 최종 하차 전에는 `빠른하차`로 구분된다.
- [ ] 엘리베이터 정보가 없거나 충돌하면 경로를 숨기지 않고 `안전 경로 미확인`으로 표시한다.
- [ ] 운행 중지 시설이 있으면 해당 시설을 안전 경로로 추천하지 않는다.

## 4. 검색과 역 선택

- [ ] 출발역에 입력한 검색어가 도착역 입력란에 복사되지 않는다.
- [ ] 검색 결과의 역명, 호선 배지와 색상이 실제 노선과 일치한다.
- [ ] 환승역은 지원하는 여러 호선 배지를 함께 표시한다.
- [ ] 같은 이름의 역은 노선 배지로 구분할 수 있다.
- [ ] 검색 결과 없음과 지원하지 않는 역을 서로 다른 문구로 안내한다.
- [ ] 출발역과 도착역을 교환하면 두 값과 경로가 함께 갱신된다.
- [ ] 같은 역을 출발·도착으로 선택하면 이해할 수 있는 오류를 표시한다.
- [ ] 지도와 텍스트 검색에서 같은 역을 선택하면 동일한 역 코드가 사용된다.

## 5. 여정 결과와 안내 문구

- [ ] 경로가 존재하면 일부 엘리베이터 데이터가 없어도 일반 열차 경로를 표시한다.
- [ ] 정말 지원하지 않는 조합과 시설 데이터 미확인을 구분한다.
- [ ] 단일 출구는 `X번 출구 쪽 지상 엘리베이터`라고 안내한다.
- [ ] 복수 출구는 `X, Y번 출구 중 가까운 출구의 지상 엘리베이터`라고 안내한다.
- [ ] 탑승 엘리베이터 카드에는 불필요한 양방향 차량·문 위치를 함께 노출하지 않는다.
- [ ] 퇴장 엘리베이터 카드는 하차 문 부근 위치와 이동 층을 간결하게 안내한다.
- [ ] 열차 카드는 노선, 목적역, 빠른환승 또는 빠른하차 위치, 종착역행을 표시한다.
- [ ] `승강장 간격 안전`, `유의`, `추천 제외`, `미확인`이 색상뿐 아니라 텍스트로도 구분된다.
- [ ] 기술적인 API 출처 충돌 설명이나 내부 근거가 기본 사용자 카드에 과도하게 노출되지 않는다.
- [ ] 안내 단계 번호가 빠지거나 중복되지 않고 위에서 아래로 이동 순서와 일치한다.

## 6. 승강기 상태와 실패 처리

- [ ] 운행 중인 필수 승강기는 정상 상태로 표시된다.
- [ ] 운행 중지 승강기는 위험 경로에서 제외되고 대체 경로 또는 미확인 안내가 나온다.
- [ ] 실시간 상태를 조회하지 못한 경우 `운행 중`으로 추정하지 않고 `상태 미확인`으로 표시한다.
- [ ] 원천 동선 정보가 없으면 `안전 경로 미확인`이지만 일반 열차 이동은 계속 제공한다.
- [ ] API 연결 실패, 지원 밖, 데이터 누락, 상태 미확인의 사용자 문구가 서로 구분된다.
- [ ] `대체 경로 다시 찾기`를 눌러도 같은 고장 시설을 다시 필수 경로로 추천하지 않는다.

## 7. 오프라인과 재실행

1. 정상 여정을 조회하고 이동 순서를 확인한다.
2. Wi-Fi와 셀룰러를 모두 끈다.
3. 앱을 완전히 종료한 뒤 다시 실행한다.

- [ ] 동일한 출발역·도착역과 여정이 복구된다.
- [ ] 저장된 전체 이동 순서가 같은 순서로 복구된다.
- [ ] 저장 시각이 표시되고 실시간 상태가 오래된 정보임을 구분한다.
- [ ] 오프라인에서도 저장된 안내 내용을 읽을 수 있다.
- [ ] 새 여정을 검색하면 이전 snapshot이 새 여정으로 교체된다.
- [ ] 손상되거나 버전이 맞지 않는 snapshot은 잘못된 경로로 복구되지 않는다.

## 8. 큰 글자와 화면 배치

iOS는 설정의 `디스플레이 및 텍스트 크기 → 더 큰 텍스트`, Android는 `글꼴 크기 및 스타일`에서 가장 큰 단계로 확인한다.

- [ ] 검색 입력, 역명, 안내 본문과 버튼 글자가 잘리지 않는다.
- [ ] 긴 역명과 복수 출구 문구가 겹치지 않고 여러 줄로 표시된다.
- [ ] 가로 스크롤 없이 핵심 내용을 읽을 수 있다.
- [ ] 화면을 확대해도 검색, 경로 찾기, 제보와 재탐색 버튼에 접근할 수 있다.
- [ ] 상태 배지는 글자가 잘리지 않고 의미를 읽을 수 있다.
- [ ] 키보드가 열린 상태에서도 검색 결과와 닫기 버튼을 사용할 수 있다.

## 9. VoiceOver와 TalkBack

- [ ] 화면 제목 → 출발역 → 도착역 → 검색 버튼 순서로 읽힌다.
- [ ] 역 배지는 색상만 읽지 않고 `5호선`, `공항철도`처럼 노선명을 읽는다.
- [ ] 여정 카드는 단계 번호, 유형, 역명, 핵심 안내, 상태 순으로 읽힌다.
- [ ] 장식용 아이콘과 타임라인 선을 불필요하게 읽지 않는다.
- [ ] `승강장 간격 안전/유의/미확인` 상태를 음성으로 구분한다.
- [ ] 버튼은 동작을 알 수 있는 이름으로 읽히며 `버튼` 역할이 전달된다.
- [ ] 스와이프만으로 모든 핵심 단계와 오류 제보 기능에 도달할 수 있다.
- [ ] 포커스가 화면 밖이나 이미 닫힌 팝업으로 이동하지 않는다.

## 10. 오류 제보와 서비스 정보

- [ ] 각 단계에서 `이 단계 정보 제보`를 열 수 있다.
- [ ] 제보 내용에 여정 ID, 데이터 버전, 단계와 시설 ID가 자동으로 포함된다.
- [ ] 사용자가 오류 유형과 설명을 수정할 수 있다.
- [ ] 사용자 확인 전에는 메일이 자동 전송되지 않는다.
- [ ] 메일 앱이 있으면 작성 화면이 열리고, 없으면 주소와 내용을 복사할 수 있다.
- [ ] 위치 좌표나 불필요한 위치 이력이 제보에 포함되지 않는다.
- [ ] 개인정보 처리방침, 이용약관과 지원 화면이 열린다.
- [ ] 저장된 현재 여정을 사용자가 삭제할 수 있다.

## 11. 플랫폼 기본 동작

### iOS

- [ ] 첫 실행, 백그라운드 복귀와 강제 종료 후 재실행이 정상이다.
- [ ] 화면 상단·하단 안전 영역과 홈 인디케이터가 내용을 가리지 않는다.
- [ ] VoiceOver 사용 중 뒤로 가기와 모달 닫기가 가능하다.
- [ ] 필요하지 않은 위치, 카메라, 마이크와 추적 권한을 요청하지 않는다.

### Android

- [ ] 시스템 뒤로 가기가 이전 화면 또는 모달 닫기로 동작한다.
- [ ] 예측 뒤로 가기 또는 제스처 뒤로 가기에서 앱이 종료되지 않는다.
- [ ] TalkBack 사용 중 검색 결과 선택과 여정 스크롤이 가능하다.
- [ ] 필요하지 않은 위치, 카메라, 마이크, 연락처와 광고 ID 권한을 요청하지 않는다.

## 12. 출시 차단 판정

아래 중 하나라도 발견되면 출시를 중단하고 해당 경로를 수정하거나 `안전 경로 미확인`으로 전환한다.

- [ ] 잘못된 진행 방향 또는 존재하지 않는 출구를 안전 경로로 추천한다.
- [ ] 운행 중지 승강기를 필수 경로로 추천한다.
- [ ] 데이터 미확인을 안전으로 표시한다.
- [ ] 앱 시작, 역 검색 또는 결과 화면 진입이 불가능하다.
- [ ] 저장한 여정이 다른 출발역·도착역으로 복구된다.
- [ ] 정상적인 일반 열차 경로가 있는데 시설 정보 부족만으로 전체 경로를 숨긴다.

출시 차단 항목이 없고, 두 대표 여정과 iOS·Android 필수 항목을 모두 통과하면 [`출시 관문 문서`](../release/t23-launch-gate.md)에 결과를 반영한다.

## 13. 발견 문제 기록

| 심각도 | 플랫폼·기기 | 출발 → 도착 | 단계 | 실제 결과 | 기대 결과 | 화면·로그 | 상태 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Blocker / Major / Minor |  |  |  |  |  |  | Open |

심각도 기준:

- `Blocker`: 위험한 경로 추천, 앱 진행 불가, 다른 여정 복구
- `Major`: 핵심 안내 누락, 접근성으로 핵심 기능 사용 불가, 제보 대안 실패
- `Minor`: 의미를 바꾸지 않는 문구·간격·정렬 문제
